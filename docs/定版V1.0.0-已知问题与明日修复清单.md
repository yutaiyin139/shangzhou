## R2　`dify_accounts.phone` 无唯一约束，且"空"用的是空串（我提的修法有坑，务必读第三条）

- **现象**：定版前发现 `yu` 与 `yutaiyin` 共用手机号 `13911111170`。找回密码按 `email OR phone` + `fetchone()` 定位账号 → 同号两人会错配（重置给错的人 / 另一个人找不回）。
- **本次已做**：`yu` 的手机号改为 `18611104728`（`UPDATE` 影响 1 行，独立连接读回，重复归零，交叉撞车 0）。**回滚值：`yu.phone = 13911111170`**。
- **还没做（明日）**：
  1. `phone` 列是 `VARCHAR(20) DEFAULT ''`（`backend/models/tables.py` 的 `DIFY_ACCOUNTS_TABLE_SQL`）。
  2. 表定义里目前**只有 `uk_email`**，没有任何手机号唯一约束（我核对过 L628-643）。
  3. **直接 `ALTER TABLE ... ADD UNIQUE KEY (phone)` 会引入新 bug**：MySQL 唯一键允许多个 `NULL`，但**不允许多个空串** → 第二个"注册时不填手机号"的账号会因主键冲突注册失败。
  4. 正确顺序：先把"空手机号"统一成 `NULL`（改列默认值 + 注册写入 + `PUT /api/account` 写入三处），再 `ALTER ADD UNIQUE KEY uk_account_phone (phone)`，最后补一条"两个账号都不填手机号仍能注册"的用例。
- **验证命令**：`SELECT name, phone FROM dify_accounts;`（当前 `鼎正` 为空，只能用邮箱找回）+ `SHOW INDEX FROM dify_accounts;`

## R5　13 处 `request.user_id` 修复只有静态保证

- **背景**：`request.user_id` 这个属性 Flask 从来就没有，一调用即 `AttributeError` → 500。已全量改成 `_safe_uid(None)`。
- **已实测**：`/api/plugins`、`/api/plugins/installed`、`/api/agent-templates` 等 2 处在真实 `:5000` 上拿到 200。
- **未实测**：其余 13 处位于 **POST/PUT 分支**，目前只有「模块级 import + `compileall` + 全仓 `request.user_id` 零残留」三重静态保证。路由扫描器默认只打 GET，所以它不在扫描覆盖内。
- **建议**：明日对这 13 个端点逐个打真实请求（用 `check_routes_5xx.py --include-write`，它会跑写接口隔离检查；**先确认库里探针自清**），或直接跑 `verify_ownership_enforcement.py`。

## R6　发布清理脚本 `scripts/clean-for-release.bat` 的 8 处缺口

- **现状更新**：今天工作区已初始化 git，`.gitignore` 经核对**确实挡住了** `.env`、`backend/.jwt_secret`、`backend/.encryption_key`、`front/node_modules`(94MB)、`qdrant`(540MB)、`Redis-8.10.1`(52MB)、`front/dist`、`logs/`、`backend/cache/`、`_tmp_*.py`；`git ls-files` 跟踪 359 个文件，其中运行时/依赖/缓存/二进制 **0 个入库**。所以"打包泄密"的风险已大幅下降，脚本问题降级为不阻断。
- **仍存的缺口**（明天顺手修，逐条都是我实测过的）：
  1. 会删 `backend/venv_libs/`，而 3 个脚本从那里 import → 删完这几个脚本直接 ImportError；
  2. 对 `redis.conf` 生成 `.bak` 的行为不可逆（重复运行会用 `.bak` 覆盖已改好的配置）；
  3. 整体删 `logs/`，但 `start-*.bat` 假定目录存在 → 下次启动报错；
  4. 漏清 `.claude/`（若还在，内含大量探测快照与账号列名等信息）；
  5. 前端产物目录名写错（`front/build` vs 实际的 `front/dist`）；
  6. 无打包体积核对/清单输出，删多了也看不出来；
  7. 无"只读预览"模式，一跑就真删；
  8. 与 `.gitignore` 职责重叠但规则不同步，两处容易各说各话。
- **建议**：既然已有 git，改为以 `git archive` / `git clean -xdn` 预览 + 白名单打包为准，把这个脚本退化成"人工确认后的兜底"。
