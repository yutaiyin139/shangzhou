# 熵舟·智能体工作台 —— 生产环境部署手册（V1.0 封版）

> 版本：**V1.0**（发布定版）
> 适用系统：Ubuntu 22.04 / 24.04 LTS（生产），Windows 10/11（本地开发联调）
> 文档目标：从零把平台部署到一台 Linux 服务器并可对外提供服务，含配置、初始化、验证、备份、安全加固与故障排查。

---

## 1. 系统架构

熵舟为**前后端分离**架构，生产由 Nginx 统一入口，后端用 Gunicorn 承载，异步任务用 Celery（Redis 作 broker）。

| 组件 | 技术 | 默认端口 | 作用 |
|------|------|---------|------|
| 前端 | Vue 3 + Vite（构建为静态 `dist`） | 由 Nginx 提供（80/443） | 工作台 UI、工作流画布、应用运行 |
| 后端 API | Flask + Flask-SocketIO + Gunicorn(gevent/gthread) | 5000（仅内网） | 业务接口、工作流引擎、LLM 调用 |
| 数据库 | MySQL 8.0（库名 `szagent`，utf8mb4） | 3306 | 全部业务/工作流/用户数据持久化 |
| 缓存/队列 | Redis 7.x | 6379 | Celery broker/backend + 应用缓存 |
| 向量库 | Qdrant（可选，回退 MySQL 冗余检索） | 6333 / 6334 | 知识库检索、Agent 记忆 |
| 异步任务 | Celery Worker + Beat | — | 向量化、定时触发、工作流异步运行 |
| 反向代理 | Nginx | 80 / 443 | 静态托管、`/api/` `/ws/` 反代、SSL |

请求链路：`浏览器 → Nginx(80/443) → 静态资源` ；`/api/* → Gunicorn(5000)` ；`/ws/* → SocketIO` ；耗时任务 `后端 → Redis 队列 → Celery Worker`。

> 队列约定：Celery 任务按路由分发到 `workflow`、`embedding`、`scheduled` 三个命名队列。
> **Worker 必须消费全部队列**：`-Q workflow,embedding,scheduled`，否则入队任务（如知识库向量化）会永久 PENDING。

## 2. 环境要求

- CPU：≥ 4 核；内存：≥ 8 GB（向量检索与大模型并发建议 16 GB）；磁盘：≥ 50 GB。
- 操作系统：Ubuntu 22.04 / 24.04 LTS，具备 root 或 sudo 权限。
- 软件版本：Python 3.10+（推荐 3.12/3.13）、Node.js 18+ LTS、MySQL 8.0、Redis 7.x、Nginx。
- 网络：可访问所配置模型厂商 API（DeepSeek / 月之暗面等）出网 443。
- 端口放行：对外仅暴露 80/443；3306/6379/6333/5000 仅限内网。

## 3. 部署方式 A：一键部署（推荐）

仓库自带 `scripts/deploy-ubuntu.sh`，交互式完成系统初始化、依赖安装、代码部署、前端构建、Nginx/systemd/备份/防火墙配置。

### 3.1 上传代码

```bash
# 本地：把项目打包上传（排除依赖与缓存）
scp -r shangzhou/ user@server:/tmp/

# 服务器
sudo bash /tmp/shangzhou/scripts/deploy-ubuntu.sh
```

### 3.2 向导输入

脚本会依次询问：**域名**（留空=用 IP 的 HTTP 访问）、**SSL 邮箱**、**MySQL root/应用密码、Redis 密码**（留空自动生成强随机值）。部署结束后，所有生成的凭据写入 `/opt/szagent/.credentials`（权限 600），**请立即妥善保存**。

### 3.3 非交互 / 覆盖默认（环境变量注入）

```bash
sudo DOMAIN="ai.example.com" EMAIL="ops@example.com" SETUP_SSL=true \
     MYSQL_DB_PASSWORD='StrongP@ss' REDIS_PASSWORD='StrongR@ss' \
     DEPLOY_DIR=/opt/szagent \
     bash /tmp/shangzhou/scripts/deploy-ubuntu.sh
```

可覆盖变量：`DEPLOY_USER` `DEPLOY_DIR` `DATA_DIR` `MYSQL_DB_NAME/USER/PASSWORD` `REDIS_PASSWORD` `JWT_SECRET` `FLASK_SECRET` `BACKEND_PORT` `FRONTEND_PORT` `USE_DOCKER_QDRANT` `SETUP_SSL` `GIT_REPO` `GIT_BRANCH`。

### 3.4 脚本执行步骤（16 步概览）

1 系统更新与基础工具 → 2 创建用户/目录 → 3 安装 MySQL → 4 安装 Redis → 5 安装 Qdrant（Docker 或二进制）→ 6 安装 Python/Node → 7 部署代码 → 8 后端环境（生成 `.env`、建 venv、装依赖、初始化建表、Gunicorn 配置）→ 9 构建前端 `dist` → 10 配置 Nginx（HTTP 站点）→ 11 配置 SSL（有域名时 certbot 升级为 HTTPS）→ 12 创建 systemd 服务（后端 + Worker）→ 13 定时备份 → 14 日志轮转 → 15 防火墙 UFW → 16 部署验证。

### 3.5 验证

```bash
sudo systemctl status szagent-backend szagent-worker nginx
curl -s http://localhost:5000/api/health      # 期望 status=healthy
curl -I http://localhost                        # 期望 200（Nginx）
```

浏览器访问 `http://<服务器IP>` 或 `https://<域名>`，用**初始管理员账号 `yutaiyin`** 登录（见 §6）。

> 说明：`SETUP_SSL=true` 时 Nginx 先以 HTTP 站点启动，certbot 成功后自动加入 443 与 HTTP→HTTPS 跳转；未配置域名时保持纯 HTTP，IP 可直接访问。

### 3.6 部署方式 A-2：跨网 SSH 在线一键部署（实测 V1.0）

与 §3.1（在目标机上跑 `deploy-ubuntu.sh`）不同，本方式**从本地 Windows 通过 SSH/SFTP 编排**：上传后端代码 + 已构建前端 `dist`，再在目标机执行服务端脚本。适用于目标机**无 Node / 无 git、MySQL 为远程实例**的场景。

交付物：
- `scripts/deploy_ubuntu_online.py`：Windows 侧驱动（paramiko），负责上传 + 触发。
- `scripts/deploy-ubuntu-online.sh`：服务端一键脚本（`set -euo pipefail`），8 步完成。

关键前提与设计取舍：
- **纯 Python DB 驱动 PyMySQL**：无需 `mysqlclient`/`libmysqlclient` 编译，可直接连远程 MySQL。
- **gunicorn `gthread` 模型**：`-w 4 -k gthread --threads 8`。前端仅用相对 `/api` + SSE、不依赖 socket.io 长连接，故规避 Python 3.14 无 `gevent` wheel 的问题。
- **前端用已构建 `dist`**：目标机不装 Node；`dist` 上传后由 Nginx 直接托管。
- **Qdrant 用本机二进制**（如 `/usr/local/bin/qdrant`）注册为 systemd 服务，而非 Docker；二进制缺失则自动跳过，后端回退 MySQL 余弦检索。

驱动侧环境变量（覆盖默认连接）：

```bash
$env:SZ_HOST="172.28.186.196"; $env:SZ_USER="yuty"; $env:SZ_PASS="0000"
$env:SZ_APP_DIR="/home/yuty/shangzhou"
python scripts/deploy_ubuntu_online.py            # 上传 + 部署
python scripts/deploy_ubuntu_online.py --upload-only   # 仅上传
python scripts/deploy_ubuntu_online.py --run-only      # 仅重跑服务端脚本
```

服务端脚本环境变量（写入远端 `.env` 与 systemd）：`APP_DIR` `APP_USER` `BACKEND_PORT` `HTTP_PORT` `DB_HOST` `DB_PORT` `DB_USER` `DB_PASSWORD` `DB_NAME` `REDIS_HOST` `REDIS_PORT` `QDRANT_ENABLE`。

服务端脚本 8 步：1 apt 装 `python3-venv/pip/dev build-essential libffi/libssl pkg-config redis-server nginx curl rsync` → 2 生成 `.env`（`JWT_SECRET`/`SECRET_KEY` 用 `secrets.token_hex` 随机）→ 3 建 venv + 装 `requirements.txt` + `gunicorn` → 4 权限（`chown $APP_USER`、`.env` 640、逐级放开目录穿越位让 nginx 读 `home` 下 `dist`）→ 5 三套 systemd（`User=$APP_USER`）+ 原生 Qdrant 单元 → 6 Nginx 站点（SPA 回退 + `/api/` 反代 + `proxy_buffering off` 支持 SSE，删 `sites-enabled/default`）→ 7 启动全部服务 → 8 轮询 `/api/health` 与前端 200。

> **V1.0 实测记录**（Ubuntu 26.04 / Python 3.14.4 / 远程 MySQL 9.7）：六项服务 `szagent-backend`/`worker`/`beat`/`qdrant`/`redis-server`/`nginx` 均 `active`；`/api/health` = **healthy**（mysql/redis/celery 连通）；外部 `http://<服务器IP>/` = **200**；`yutaiyin` 登录后 `GET /api/workflows-app` 返回 **200**、35 个工作流应用。
>
> 注意：远程 MySQL 若仅授予 `root@'localhost'`，则**远程 `root` 必被拒**，应用账号须用具备 `@'%'` 远程授权的用户（本例 `DB_USER=yuty`）。

## 4. 部署方式 B：手动分步部署

适合需要精细控制或对现有环境集成的场景。约定：代码目录 `/opt/szagent`，数据目录 `/var/lib/szagent`，运行用户 `szagent`。

### 4.1 基础依赖

```bash
sudo apt update && sudo apt -y upgrade
sudo apt -y install git curl wget build-essential \
    python3 python3-pip python3-venv python3-dev \
    default-libmysqlclient-dev pkg-config libffi-dev libssl-dev \
    nginx certbot python3-certbot-nginx ufw
```

Node.js 18：
```bash
curl -fsSL https://deb.nodesource.com/setup_18.x | sudo -E bash -
sudo apt -y install nodejs
```

### 4.2 MySQL

```bash
sudo apt -y install mysql-server
sudo mysql -u root <<'SQL'
CREATE DATABASE IF NOT EXISTS szagent CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER IF NOT EXISTS 'szagent'@'localhost' IDENTIFIED BY 'StrongP@ss';
GRANT ALL PRIVILEGES ON szagent.* TO 'szagent'@'localhost';
FLUSH PRIVILEGES;
SQL
```
> 必须 **utf8mb4**：应用模板/图标含 emoji，utf8mb3 会把其写成 `?` 破坏 DSL YAML。

### 4.3 Redis

```bash
sudo apt -y install redis-server
# /etc/redis/redis.conf 设置：requirepass StrongR@ss ；bind 127.0.0.1
sudo systemctl restart redis-server
```

### 4.4 Qdrant（可选，缺失时系统回退 MySQL 冗余检索）

```bash
sudo mkdir -p /var/lib/qdrant/{storage,snapshots}
sudo docker run -d --name qdrant --restart unless-stopped \
  -p 6333:6333 -p 6334:6334 \
  -v /var/lib/qdrant/storage:/qdrant/storage \
  qdrant/qdrant:latest
```

### 4.5 部署代码与后端

```bash
sudo useradd -m -s /bin/bash szagent || true
sudo mkdir -p /opt/szagent /var/lib/szagent/{logs,backups,uploads}
# 拷贝代码（git clone 或 rsync），随后：
sudo chown -R szagent:szagent /opt/szagent /var/lib/szagent

cd /opt/szagent
sudo -u szagent python3 -m venv venv
sudo -u szagent bash -c "
  source venv/bin/activate
  pip install -U pip setuptools wheel
  pip install -r backend/requirements.txt
  pip install gunicorn gevent python-dotenv
"
```

生成 `/opt/szagent/.env`（见 §5），权限 600，属主 szagent。

数据库建表在**后端启动时自动完成**（各路由 `init_tables()` 执行 `CREATE TABLE IF NOT EXISTS`）。如需显式初始化：
```bash
sudo -u szagent bash -c "cd /opt/szagent/backend && source ../venv/bin/activate && \
  python -c \"import models.tables as T,config; db=config.get_db(); c=db.cursor(); \
  [c.execute(getattr(T,n)) for n in dir(T) if n.endswith('_TABLE_SQL') and isinstance(getattr(T,n),str) and getattr(T,n).lstrip().upper().startswith('CREATE')]; \
  db.commit(); db.close(); print('tables ready')\""
```

### 4.6 构建前端

```bash
cd /opt/szagent/front
sudo -u szagent bash -c "npm install && npm run build"   # 产物 dist/
```

### 4.7 Nginx（HTTP 站点，先跑通再上 SSL）

`/etc/nginx/sites-available/szagent`：
```nginx
server {
    listen 80;
    listen [::]:80;
    server_name _;                       # 有域名改为 ai.example.com

    root /opt/szagent/front/dist;
    index index.html;

    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    client_max_body_size 50M;

    location = /health { proxy_pass http://127.0.0.1:5000/api/health; access_log off; }

    location /api/ {
        proxy_pass http://127.0.0.1:5000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 300s;
    }
    location /ws/ {
        proxy_pass http://127.0.0.1:5000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 86400;
    }
    location / { try_files $uri $uri/ /index.html; }
}
```
```bash
sudo rm -f /etc/nginx/sites-enabled/default
sudo ln -sf /etc/nginx/sites-available/szagent /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl restart nginx
```

### 4.8 启用 HTTPS（可选，需已解析域名）

```bash
sudo mkdir -p /var/www/certbot
sudo certbot --nginx -d ai.example.com --email ops@example.com \
     --agree-tos --no-eff-email --redirect --hsts
sudo systemctl enable certbot.timer
```

### 4.9 systemd 服务

后端 `/etc/systemd/system/szagent-backend.service`：
```ini
[Unit]
Description=Shangzhou Backend
After=network.target mysql.service redis-server.service
Wants=mysql.service redis-server.service
[Service]
User=szagent
WorkingDirectory=/opt/szagent/backend
EnvironmentFile=/opt/szagent/.env
ExecStart=/opt/szagent/venv/bin/gunicorn -c gunicorn.conf.py app:app
Restart=always
[Install]
WantedBy=multi-user.target
```

Worker `/etc/systemd/system/szagent-worker.service`（**含 Beat，消费全部队列**）：
```ini
[Unit]
Description=Shangzhou Celery Worker+Beat
After=network.target redis-server.service
[Service]
User=szagent
WorkingDirectory=/opt/szagent/backend
EnvironmentFile=/opt/szagent/.env
ExecStart=/opt/szagent/venv/bin/celery -A tasks.celery_app worker -B --loglevel=info -Q workflow,embedding,scheduled --concurrency=4
Restart=always
[Install]
WantedBy=multi-user.target
```
```bash
sudo systemctl daemon-reload
sudo systemctl enable --now szagent-backend szagent-worker
```

## 5. 配置参考（`.env`）

后端 `config.py` 启动时自动加载项目根 `.env`；systemd 亦通过 `EnvironmentFile` 注入。关键变量：

| 变量 | 示例 | 说明 |
|------|------|------|
| `DB_HOST`/`DB_PORT` | `127.0.0.1` / `3306` | MySQL 地址 |
| `DB_USER`/`DB_PASSWORD` | `szagent` / 强密码 | 数据库账号 |
| `DB_NAME` | `szagent` | 库名 |
| `REDIS_HOST`/`REDIS_PORT` | `127.0.0.1` / `6379` | Redis 地址 |
| `REDIS_PASSWORD` | 强密码 | **Celery broker 连接串会带上该密码**（留空表示无密码） |
| `JWT_SECRET` | ≥32 随机串 | 令牌签名密钥，泄露=可伪造登录 |
| `JWT_ACCESS_EXPIRY`/`JWT_REFRESH_EXPIRY` | `7200` / `604800` | 令牌有效期（秒） |
| `ENCRYPTION_KEY` | Fernet/base64 密钥 | **加密模型 API Key**；一旦启用不可更换，丢失将无法解密已存密钥，务必离线备份 |
| `SECRET_KEY` / `FLASK_SECRET` | 随机串 | Flask 会话密钥 |
| `FLASK_DEBUG` | `0` | **生产必须为 0** |
| `LOG_LEVEL`/`LOG_FILE` | `INFO` / `/var/lib/szagent/logs/backend.log` | 日志 |

生成随机密钥：`openssl rand -base64 32`。`.env` 权限 `chmod 600`，属主运行用户。

> 模型凭证：LLM 的 API Key 通过平台「模型/Provider」配置界面录入并**加密入库**，或通过 `scripts/seed_*.py` 预置。Key 的加解密依赖 `ENCRYPTION_KEY`。

## 6. 首次初始化

1. **管理员账号**：后端启动时 `_init_default_admin()` 会创建 `admin`/`user` 角色，并把 `admin` 角色授予名为 **`yutaiyin`** 的账号。生产环境请：
   - 用 `yutaiyin` 登录，并**立即修改为其专属强密码**：
     `cd /opt/szagent/backend && ../venv/bin/python reset_password.py`（脚本位于 `scripts/maintenance/`）。
   - 如需你自己的管理员：注册普通账号后在用户管理中提升，或复用同账号。
2. **开放注册管控**：在系统设置中关闭「开放注册」或改为受控注册（P0 安全项，`/api/register` 读取该配置）。
3. **配置模型 Provider**：进入「模型管理」填入 DeepSeek / 月之暗面等 API Key（保存时加密存储），连通性测试通过。
4. **知识库/应用模板**：如需内置模板，运行对应 `scripts/seed_*.py`；知识库文档上传后由 Worker 异步向量化。

## 11. 安全加固清单（V1.0 发布基线）

- [ ] `.env` / `.credentials` 权限 `600`，属主运行用户，**不入库不入镜像**。
- [ ] `FLASK_DEBUG=0`；`JWT_SECRET`、`REDIS_PASSWORD`、DB 密码均为强随机值。
- [ ] 修改默认管理员 `yutaiyin` 密码；关闭或管控「开放注册」。
- [ ] UFW 仅放行 `22/80/443`；`3306/6379/6333/5000` 只监听内网。
- [ ] 配置域名 + HTTPS + HSTS；HTTP 80 端口跳转 443。
- [ ] 定期校验 `backup.log`，异地保存数据库与密钥备份。
- [ ] 仓库/镜像中移除本地 `backend/.encryption_key`（生产用 `ENCRYPTION_KEY` 环境变量）。

## 12. 故障排查

| 现象 | 根因 | 处理 |
|------|------|------|
| `/api/health` = `degraded` | Redis 未运行 → Celery 不可达 | 启动 `redis-server`，确认 `REDIS_PASSWORD` 匹配 |
| 知识库向量化一直 PENDING | Worker 未消费 `embedding` 队列 | 以 `-Q workflow,embedding,scheduled` 启动 Worker |
| 健康检查通过但部署脚本报错 | 文件为 CRLF，`bash` 报 `\r`/括号语法错 | 用 `dos2unix`/LF 保存；本手册脚本已修正为 LF |
| 工作流运行"成功"但拿不到最终报告 | 结束节点未解析 `outputs` | 已修复 `engine/node_factory.py:_node_end`；升级后端代码并重启 |
| Kimi/月之暗面聊天 HTTP 400 | `temperature` 被硬编码为 0.7 | 已在 `routes/chat.py` 改读模型配置；工作流节点走 `completion_params` |
| 模板创建 "mapping keys are not allowed" | emoji 图标被 MySQL utf8mb3 写成 `?` | 确保库/连接为 `utf8mb4` |
| 端口被占用 | 旧进程未退出 | `stop-backend.bat`/`stop-front.bat`，或 `lsof -i:5000` 后清理 |
| Nginx 502 | 后端/Gunicorn 未起或崩溃 | `journalctl -u szagent-backend`，确认 5000 监听 |
| 登录返回 `423`「当前 IP 已被锁定」 | 多次登录失败触发 IP 级锁定（非密码错误） | 用 `unlock_account(username, ip=...)` 清锁，或等锁定期过；避免反复试错 |
| 部署脚本报 `conflicting server name "_" on :80` | Ubuntu 默认站点与本站点冲突 | `rm -f /etc/nginx/sites-enabled/default` 后 `nginx -t && systemctl restart nginx` |
| 远程连 MySQL 报 `Access denied for user 'root'@...` | 目标库仅授予 `root@'localhost'` | 应用账号改用具备 `@'%'` 远程授权的用户（如 `DB_USER=yuty`） |
